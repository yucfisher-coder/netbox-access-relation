# 系统地址、归并与合并部署

来源基线：R04–R05。状态：已确认。

## 系统地址

| ID | 需求 |
|---|---|
| REQ-ADDR-001 | 每条 `SystemAddress` 必须且只能关联一个 NetBox Prefix、IPAddress 或 IPRange。 |
| REQ-ADDR-002 | 不复制原生对象的地址、VRF 或安全区域值。 |
| REQ-ADDR-003 | 同一系统不能重复关联同一原生对象；一个原生对象允许被多个系统共享。 |
| REQ-ADDR-004 | 删除系统地址默认只解除关联；被引用原生对象受保护，单独删除时必须先处理引用。 |
| REQ-ADDR-005 | 一个业务系统可在一次提交中新增、修改或解除多条地址关联；整批操作共同校验并使用单一事务，任一条失败时不得产生部分写入。 |
| REQ-ADDR-006 | 新增地址时，每一行只允许选择“关联已有 IPAM 对象”或“创建新 IPAM 对象”；“更新当前关联的 IPAM 对象”只适用于已经存在的地址关联，不得出现在新增行中。 |
| REQ-ADDR-007 | 地址操作必须先选择操作方式和 Prefix、IPAddress 或 IPRange 类型，再只接受该组合所需字段；隐藏字段或其他操作方式的残留值不得参与保存。 |
| REQ-ADDR-008 | 编辑现有地址关联时，可以修改当前原生对象或改为关联另一个已有对象；解除关联是独立且明确的操作，默认不删除原生对象。 |

原生对象权限与联合事务见 `authorization-api.md` 的 REQ-AUTH-002、REQ-TXN-001～002。

## 地址归并与合并部署

| ID | 需求 |
|---|---|
| REQ-MERGE-001 | 只合并同一系统、同一地址族、同一已解析 VRF、同一安全区域解析状态和值的单 IP 或显式范围。 |
| REQ-MERGE-002 | 仅合并重叠或严格连续且不会填补源数据空隙的区间。 |
| REQ-MERGE-003 | 单地址保留为 IPAddress，CIDR 保留为 Prefix，不展开 CIDR 后合并。 |
| REQ-MERGE-004 | VRF 未解析或歧义、或者合并结果与现有非完全相同 IPRange 重叠时，不自动创建 IPRange；区域为空不阻止保存，但不得跨不同区域结果合并。 |
| REQ-MERGE-005 | 只有同一个原生对象被多个系统关联时才标记相关系统为“合并部署”；地址包含、相交或显示值相同不算，关联变化后自动重算。 |
