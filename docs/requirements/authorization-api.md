# 权限、API、审计、事务与状态

来源基线：R04、R09–R11。状态：已确认。

## 权限

| ID | 需求 |
|---|---|
| REQ-AUTH-001 | 使用 NetBox 用户、组、对象权限、认证和限流；列表、详情、筛选、导出、API、统计和下钻使用同一对象权限范围。 |
| REQ-AUTH-002 | 业务系统地址操作除插件对象权限外，还必须检查对应 Prefix、IPAddress 或 IPRange 的查看、新增或修改权限。 |
| REQ-AUTH-003 | 无权对象不得通过计数、筛选选项、导出内容或错误信息泄露。 |

业务系统、别名、地址关联、访问关系和导入分别授权；后台操作代表发起用户执行。

## API

| ID | 需求 |
|---|---|
| REQ-API-001 | REST API 为核心对象提供查询、筛选、分页及有权限的增删改。 |
| REQ-API-002 | API 与页面、导入使用相同业务规则，不建立旁路校验。 |

## 审计与事务

| ID | 需求 |
|---|---|
| REQ-AUDIT-001 | NetBox 原生变更记录记录最终业务对象的新增、修改和删除。 |
| REQ-TXN-001 | 新建或修改原生地址及其业务关联使用 NetBox 原生校验并处于同一数据库事务。 |
| REQ-TXN-002 | 权限拒绝或校验失败不得产生部分写入。 |

## 状态边界

| ID | 需求 |
|---|---|
| REQ-STATE-001 | 关系有效状态与区域解析状态使用不同术语，不共用含义含混的“状态”。 |
| REQ-STATE-002 | 空数据、无匹配、无权限和计算异常必须明确区分。 |
