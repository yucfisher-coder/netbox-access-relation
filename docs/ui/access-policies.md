# 访问关系页面规格

需求引用：REQ-POL-001～007、REQ-SVC-001～007、REQ-QUERY-001～002、REQ-AUTH-001～003。

## 页面目标

维护两个业务系统之间有方向的访问需求，并展示两端系统当前全部地址及服务项。

## 列表页

至少展示关系名称、分类、源端和目标端完整 IPAM 证据、协议与端口、有效期、有效状态和备注。
每端 IPAM 证据按地址逐项展示原生对象类型、地址或范围、VRF、匹配 Prefix、安全区域和区域解析
状态；有权限时地址、Prefix 和 VRF 可跳转到 NetBox 原生对象。默认显示用户有权查看的全部关系，
包括已失效关系。

筛选面板提供独立的“分类”输入行，并支持按名称、分类、源/目标/任一系统、IP、源/目标/任一区域、协议、单端口或端口范围、有效状态
组合筛选。组合语义采用 REQ-QUERY-002，服务匹配采用 REQ-SVC-005～006。操作包括新增、导入
关系及服务项、下载模板和两种 CSV 导出。

## 详情页

分区展示基本信息、源系统完整 IPAM 证据、目标系统完整 IPAM 证据、服务项和变更记录。两端证据
逐项显示原生对象类型、地址或范围、VRF、匹配 Prefix、安全区域、解析状态及有权限的原生对象链接。
页面用清晰方向表达“源系统 → 服务项 → 目标系统”，服务交集只作提示。

## 新增与编辑

表单包含唯一关系名称、分类、源系统、目标系统、生效时间、失效时间、一个或多个服务项和备注。
校验只采用 REQ-POL-001、REQ-SVC-001～003。支持提前终止并明确显示新的失效时间；服务项在
关系表单内一体化新增、编辑和删除。

提交失败后停留在当前表单并保留已填写内容。字段错误显示在对应关系字段旁，服务项错误显示在对应
服务项行，跨行冲突显示在服务项区域；权限拒绝或保存异常显示明确的页面级提示。所有失败路径均不
产生部分写入，提示不得泄露用户无权查看的对象信息。

验收场景见 `acceptance/access-policies.md`。
