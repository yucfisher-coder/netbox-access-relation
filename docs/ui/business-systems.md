# 业务系统页面规格

需求引用：REQ-SYS-001～004、REQ-ADDR-001～008、REQ-ZONE-003～006、REQ-MERGE-005、
REQ-IMP-005～007、REQ-IMP-010～014、REQ-AUTH-001～003。

## 页面目标

集中维护可作为访问关系源端或目标端的业务系统，并展示名称、别名、地址、VRF、区域证据和受影响
的访问关系。

## 列表页

至少展示系统名称、启停状态、合并部署状态、关联地址、地址类型、VRF、匹配 Prefix、安全区域、
区域解析状态和描述或备注。一个系统存在多个地址时按地址分别展示证据。

支持按名称或别名、启停状态、合并部署、IP 或网段、VRF、安全区域和区域解析状态筛选。操作包括
新增、导入系统及地址、下载模板和两种 CSV 导出。

## 详情页

分区展示基本信息、系统别名、地址与区域证据、出向关系、入向关系和变更记录。地址、匹配 Prefix
和安全区域提供原生对象跳转；异常解析状态显示原因。

## 新增与编辑

- 基本字段为名称、启停状态、描述和备注；合并部署由实际关联自动计算，不提供任意勾选。
- 别名在同一系统界面维护，不设置独立顶级菜单；命名冲突在对应字段旁提示。
- 地址区使用可重复的行式编辑器，可在一次提交中维护多条地址。现有行展示对象类型、原生对象、
  VRF、区域证据和操作状态；新增行通过“添加地址”追加。
- 每个新增行先选择“关联已有 IPAM 对象”或“创建新 IPAM 对象”，再选择 Prefix、IPAddress 或
  IPRange。页面只显示该组合需要的选择框或地址、VRF、状态、描述字段，切换操作或类型时清除不再
  适用的值。
- “更新当前关联的 IPAM 对象”不作为新增行选项，只在编辑已有地址行时提供；将关联改指向另一
  个已有对象与修改当前原生对象必须是两个明确操作。
- 解除关联使用行内明确操作并二次确认，默认不删除原生对象；具备对应权限时才显示创建、修改或
  解除操作。
- 保存时先校验全部地址行，再将业务系统、别名和地址变化置于同一事务；任一行失败时保留用户输入
  和逐行错误，不写入任何变化。
- 保存地址变化前展示受影响的入向和出向关系；删除被引用系统时阻止并引导处理引用。

## 批量导入

列表页提供“下载业务系统导入模板”和“批量导入”。模板采用 XLSX，并分别设置“业务系统”、
“系统别名”和“系统地址”工作表；三张表以业务系统规范名关联，不暴露数据库主键。

上传后进入预检页，不直接写入。预检明确展示每行将执行“新增”“关联已有”“创建并关联”“跳过
重复”或“错误”，并分别汇总数量。系统地址由对象类型、规范化地址值和 VRF 精确查找已有 IPAM
对象；找不到时才计划创建，出现多个候选、权限不足或字段冲突时阻止整批提交。无错误后由用户确认，
再以单一事务写入。首期导入不更新或删除任何已有对象；修订和解除关联仍在业务系统详情页完成。

验收场景见 `acceptance/business-systems.md`。
