# 业务系统页面验收场景

范围：REQ-SYS、REQ-ADDR、REQ-ZONE、REQ-MERGE、REQ-AUTH、REQ-STATE。

| ID | 场景 | 预期结果 | 需求 |
|---|---|---|---|
| AC-SYS-001 | 使用规范名或别名筛选 | 返回同一命名空间内精确对应的业务系统 | REQ-SYS-002～003 |
| AC-SYS-002 | 创建大小写或首尾空格不同的重名系统/别名 | 字段旁明确报冲突且不写入 | REQ-SYS-002～003、REQ-TXN-002 |
| AC-SYS-003 | 一个系统关联多种原生地址对象 | 每条地址分别显示类型、VRF、Prefix、区域及解析状态 | REQ-ADDR-001～002、REQ-ZONE-003～006 |
| AC-SYS-004 | 关联、创建或修改原生地址 | 同时校验插件和 IPAM 权限，失败时无部分写入 | REQ-AUTH-002、REQ-TXN-001～002 |
| AC-SYS-005 | 解除系统地址 | 只解除关联，不删除原生对象 | REQ-ADDR-004 |
| AC-SYS-006 | 多系统共享同一原生对象后再解除 | 合并部署状态随关联变化自动重算 | REQ-MERGE-005 |
| AC-SYS-007 | 修改地址或删除被访问关系引用的系统 | 修改前显示受影响关系；删除时阻止并提供处理引用关系的指引 | REQ-POL-005、REQ-TXN-002 |
| AC-SYS-008 | 受限用户查看列表、详情和导出 | 三者对象范围一致且不泄露无权对象 | REQ-AUTH-001～003 |
| AC-SYS-009 | 在同一业务系统中一次添加多条不同类型地址 | 所有有效地址在一次提交后出现；不需要逐条跳转和保存 | REQ-ADDR-005 |
| AC-SYS-010 | 在不同地址行选择关联已有、创建新对象或编辑现有对象 | 每行只显示当前操作和对象类型所需字段；新增行不出现“更新当前对象” | REQ-ADDR-006～008 |
| AC-SYS-011 | 批量编辑中任一地址无效、无权限或保存异常 | 所有业务系统、别名、原生对象和关联变化整体回滚，并在对应行显示错误 | REQ-ADDR-005～007、REQ-AUTH-002、REQ-TXN-001～002 |
| AC-SYS-012 | 解除一条现有地址关联 | 操作明确且需确认；只解除关联，不删除原生 IPAM 对象 | REQ-ADDR-004、REQ-ADDR-008 |
